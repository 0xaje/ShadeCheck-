# SC-003 — Selective Transaction Fetch

SC-003 evaluates transaction-ID retrieval after actual compact-block delivery. It does not observe internal wallet processing, ownership, balances, or note relevance.

## Deterministic condition

A MEDIUM finding requires all of:

- An upstream GetBlockRange response containing at least two distinct compact transaction IDs.
- At least one subsequent GetTransaction request for an ID from that response, on the same recorded transport session.
- A non-empty proper subset of those IDs requested within 30 seconds after block delivery.

The evidence contains the delivered block height, block hash, transaction IDs in protocol byte order, matching requests, response/error records when present, and the first request time delta. Compact-block serialization is SHA-256 fingerprinted. A requested ID is privacy-sensitive even if the retrieval fails, so a successful response is not required by the rule.

Transaction IDs here are actual protocol IDs, not payload SHA-256 fingerprints. Protocol bytes are reversed only when displaying a node RPC textual transaction ID.

A complete fetch of the block's compact transactions does not meet this subset condition. No fetch also does not meet it. A block with fewer than two IDs, fixture-only block delivery, or no relevant block delivery leaves coverage incomplete and returns WARN when SC-003 is selected alone. Empty evidence is an error.

The test evaluates the recorded finite trace. Later requests outside that trace or window may change the interpretation. Timing correlation is not proof of wallet relevance. The denominator is compact transactions returned by the RPC, which may exclude transparent-only transactions. This is one documented privacy heuristic, not a claim that every subset request is a vulnerability.

## Run against real regtest

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe scripts/regtest.py up
.\.venv\Scripts\python.exe scripts/selective_fetch.py
```

The script uses the existing real local wallet to create a Sapling-to-Sapling transaction and another genuine Sapling-output funding transaction. Setup broadcasts them to the local verifier and mines them together. These setup submissions are distinct from the measured retrieval behavior. The test client uses actual GetBlockRange and GetTransaction RPCs through ShadeCheck; it is a protocol-authentic test client, not a full wallet relevance scanner.

Independent node RPC checks require the compact block hash to match the canonical block and fetched bytes and confirmed inclusion to agree. No fake transaction, fabricated block, or fixture success is used. The script waits for actual lightwalletd readiness. It mines setup blocks and may confirm earlier local mempool transactions.

The two measured traces should produce:

| Behavior | SC-003 result | Strict CLI exit |
| --- | --- | --- |
| Fetch one compact transaction from a block containing at least two | MEDIUM / FAIL | 1 |
| Fetch every compact transaction returned for that block | PASS for this executed SC-003 test | 0 |

The orchestration exits 0 only after checking both expected outcomes against actual records. Reports, full events, independent backend proof, and comparison.json are saved under out/selective-fetch. JSON and HTML reports are emitted for each trace.

## Evaluate captured events

```powershell
.\.venv\Scripts\shadecheck.exe test --events <events.jsonl> --rules SC-003 --policy strict
.\.venv\Scripts\shadecheck.exe explain SC-003
```

Select both implemented rules with --rules SC-002 SC-003. Missing coverage for either selected rule prevents an overall PASS when there are no findings. Findings take precedence and fail strict policy. The existing default remains SC-002 for compatibility; SC-003 is explicitly selected. SC-001, SC-004, and SC-005 remain unimplemented.

PASS means only that no violation of this tested subset condition was observed in this executed environment. Broader fetching increases bandwidth and may have other privacy consequences; it does not establish anonymity.
