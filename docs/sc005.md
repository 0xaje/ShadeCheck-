# SC-005 — Privacy Regression

SC-005 compares a current evidence-backed result with a saved baseline under the same selected rules, correlation window, sync/payment policies, and evidence-source modes. It detects newly introduced failures, increased severity, and newly observed privacy-sensitive behavior categories. It does not infer that a code change caused the difference.

## Portable baselines

A baseline contains the complete original event trace, its recomputed base-rule report, the schema/evaluator version, and a deterministic SHA-256 baseline hash. Save validates the event hash chain and requires the supplied report to match a fresh evaluation exactly. Incomplete coverage cannot become a baseline. Loading validates the same conditions; editing a report alone cannot silently change the baseline result.

The hash is not an author signature. Someone able to rewrite the entire evidence and baseline can recompute hashes. Keep baselines and test inputs under appropriate repository review. Baselines contain the same sensitive fingerprints and local test receiver metadata as their source evidence.

Saving uses exclusive creation: an existing baseline is never silently overwritten. To intentionally accept a reviewed new reference, save to a new path. A known FAIL may be saved for diagnosis, but it remains a strict failure on later runs. A baseline does not waive privacy requirements.

## CLI

After a normal run using the default out/events.jsonl and out/report.json paths:

```sh
shadecheck baseline save
shadecheck test --events out/events.jsonl --baseline
shadecheck compare
shadecheck explain SC-005
```

For named traces, specify the paths explicitly:

```sh
shadecheck baseline save --events baseline-events.jsonl --input baseline-report.json --output baseline.json
shadecheck test --events current-events.jsonl --rules SC-001 SC-005 --config policy.json --baseline baseline.json --output comparison.json
shadecheck report --input comparison.json --format json
shadecheck report --input comparison.json --format html --output comparison.html
```

`test --baseline` appends SC-005 to the chosen base rules. Selecting SC-005 requires a baseline and at least one base rule. The existing default base rule remains SC-002. To compare an already-generated base-rule report, use:

```sh
shadecheck compare --events current-events.jsonl --input current-report.json --baseline baseline.json --output comparison.json
```

The current report is also recomputed and validated against its evidence. A comparison report cannot itself become a baseline: save its original base-rule report instead. Earlier reports may need regeneration from their original evidence after evaluator changes.

## Deterministic matching

| Comparison dimension | Treatment |
| --- | --- |
| Rule and affected component | Match behavior groups |
| SC-001 | Match the sorted set of size/alignment violations |
| SC-002 | Match connection-to-broadcast behavior; compare highest severity |
| SC-003 | Match subset retrieval behavior; compare highest severity |
| SC-004 | Match presence of transparent inputs/outputs in recorded receipts |
| Transaction IDs, hashes, sessions, timestamps, block heights, flow IDs | Retain as evidence; exclude from behavior identity |
| Duplicate findings of the same behavior | Compare highest severity; counts are not regression thresholds |
| Different rules, policy, time window, evidence modes, or evaluator version | Reject incompatible comparison |

A new group for a previously failing rule/component is labeled `new-sensitive-behavior`; a newly failing rule/component is `new-failure`. Higher severity for the same group is `severity-increased`. Each SC-005 finding embeds current evidence and, for severity escalation, baseline finding evidence. All comparisons reference the full baseline evidence root and hash, including clean baselines where there was no prior finding.

The report separately shows baseline-comparison status and overall policy status. No regression may coexist with an overall FAIL when a known base-rule finding remains. Missing current coverage yields WARN and strict exit 2; it does not produce PASS. Strict findings/regressions return exit 1. Incompatible or invalid input returns exit 2. Advisory findings return WARN with exit 0.

## Real integration on Windows

With Docker Desktop running:

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe scripts/regtest.py up
.\.venv\Scripts\python.exe scripts/regtest.py prepare-shielded
.\.venv\Scripts\python.exe scripts/regtest.py prove
.\.venv\Scripts\python.exe scripts/privacy_regression.py
```

The driver executes fresh actual GetBlockRange requests through the observer. It checks every returned block against the canonical node, saves an aligned baseline, and compares another aligned trace with a narrower unaligned trace. It also compares an aligned short request with a short unaligned request to demonstrate a newly observed violation category. An unchanged known failure remains FAIL.

Severity escalation uses an explicitly labeled prefix of an actual earlier accepted broadcast trace: the request-only observation yields MEDIUM, while the complete trace adds actual acceptance and matching mempool evidence and yields HIGH. No event is fabricated or relabeled. This demonstrates stronger observed evidence, not proof that wallet code changed or that the partial trace was rejected. Provenance files reference the original trace and evidence root.

The driver requires unchanged PASS/exit 0, new failure FAIL/exit 1, new behavior FAIL/exit 1, severity increase FAIL/exit 1, and unchanged known failure FAIL/exit 1 with zero new regressions. It also requires `test --baseline` and `compare` to produce identical results. Inspect the unique out/privacy-regression directory for portable baselines, actual traces, provenance, comparisons, and HTML reports.

## Limits

This comparison covers the documented behavior categories above, not every possible change in sensitive metadata, leak frequency, or magnitude. The developer must keep scenario, backend, and client configuration comparable; matching policy fields alone cannot establish identical experimental conditions. SC-005 can report stronger observation as increased severity. Passing means no violation of the selected rules was observed with the required coverage in this environment; it does not establish anonymity.
